# Gradeline — заметки по проекту

Документ для продолжения работы без исходной переписки.

## Что это

Gradeline — интерактивный блок для веб-страницы маршрута (design engineering study). Сделан по референсу тёмной топографической навигационной карты (`docs/reference.jpg`): 3D-рельеф с горизонталями, янтарная дорога, выноски высоты в рамке с угловыми засечками, пульсирующая точка, дорожные щиты.

Блок состоит из двух связанных видов:

- **Карта**: 3D-рельеф, дорога Hollow Pass Road, подписи, точка текущей позиции.
- **Панель**: четыре показателя (Distance, Elevation, Grade, Climbed) и профиль высот со скраббером.

Под блоком на странице есть раздел «Идея блока» на русском: четыре приёма и где блок применить.

Местность, названия и маршрут вымышленные. Рельеф генерируется кодом, внешних данных нет.

Опубликованная версия (приватный артефакт claude.ai, доступ открывает владелец через Share):
https://claude.ai/artifact/3Mr3kvM57tdL9W1GaTQnGi

## Как запустить

Сборки нет, это один HTML-файл.

1. Откройте `index.html` в браузере. Нужен интернет: Three.js r128 грузится с cdnjs, шрифты — с Google Fonts.
2. Или поднимите локальный сервер:
   ```bash
   python3 -m http.server 8080
   ```
   и откройте http://localhost:8080.

Инструменты для разработки (необязательно):

```bash
npm install
```

```bash
npm run shot
```

Скриншоты десктопа и телефона появятся в `tools/out/` (папка в .gitignore). Если cdnjs недоступен, скрипт подставит Three.js из `node_modules`.

```bash
npm run profile
```

Печатает высоты вдоль маршрута. Нужен при правке рельефа.

## Что сделано

- 3D-рельеф: сетка 320×340, высоты из функции `heightAt` (гауссовы массивы + fbm-шум). Под рельефом лежит пустынная котловина с дорогами, над ней — уступ, купол Cinder Dome и хребет Ironwood Ridge.
- Горизонтали рисуются во фрагментном шейдере через `fract(elev / step)` и `fwidth`, поэтому они чёткие при любом масштабе. Каждая 5-я (ft) или 4-я (m) линия толще.
- Маршрут: сплайн Catmull-Rom по контрольным точкам, 720 равных отрезков. Посчитаны дистанция, сглаженная высота, уклон и набор высоты.
- Единое состояние `prog` (0…1). От него зависят точка, живая выноска, курсор профиля, показатели и янтарная изолиния вокруг точки.
- Взаимодействия:
  - перетаскивание по профилю (pointer events), клавиатура на профиле (стрелки, PageUp/PageDown, Home/End, Shift — шаг крупнее);
  - наведение на рельеф подсвечивает голубым горизонталь этой высоты по всей карте и показывает её значение;
  - наведение на дорогу ставит метку на профиле, клик переносит туда точку;
  - перетаскивание по карте вращает (yaw) и наклоняет (pitch) вид, на тач-экранах — только поворот, чтобы вертикальный свайп скроллил страницу;
  - Play / Pause / Replay (маршрут за 20 с), сброс вида, переключатель ft/m.
- ft/m меняет не только цифры: шаг горизонталей становится 100 ft или 25 m, оси профиля перестраиваются.
- Подписи — HTML поверх canvas. Каждый кадр они проецируются из 3D, гаснут, если их закрывает рельеф, и не налезают друг на друга (приоритеты, см. ниже).
- Адаптив: на портретном экране камера смотрит круче и отходит дальше, чтобы дорога шла по высоте экрана. Горизонтального скролла нет на 400 px.
- Если WebGL недоступен, вместо карты показывается сообщение, профиль и показатели продолжают работать.

## Решения и почему

- **Один HTML-файл без сборки.** Проект задумывался как claude.ai-артефакт: там разрешены только внешние скрипты с cdnjs/jsdelivr/unpkg и шрифты с Google Fonts, всё остальное инлайн.
- **Three.js r128 (UMD-сборка с cdnjs).** Это последняя версия с классическим `three.min.js` на cdnjs. Используются только `WebGLRenderer`, `ShaderMaterial`, `BufferGeometry` и `Raycaster` (для луча из камеры). OrbitControls не подключён, орбита написана вручную (≈20 строк).
- **Свои шейдеры вместо стандартных материалов.** Горизонтали, подсветка изолинии, туман и затухание краёв сделаны в одном фрагментном шейдере, иначе пришлось бы рисовать линии отдельной геометрией.
- **Одна функция высоты — источник для всего.** Из сетки `HF` строятся меш, высоты дороги, профиль, уклон, проверка видимости подписей и пикинг. Поэтому карта и график не расходятся.
- **Ray marching по сетке высот вместо `Raycaster.intersectObject`.** Пикинг и проверка видимости подписей идут шагами вдоль луча с билинейной выборкой из `HF`. Это быстрее перебора 217 тыс. треугольников и годится для вызова каждый кадр.
- **Подписи в HTML, а не в WebGL.** Чёткий текст, CSS-переходы прозрачности, обычная типографика. Порядок приоритетов: точка → живая выноска → выноска перевала → щит маршрута 61 → вершины → населённые пункты → щиты дорог → название котловины → выноска нижней точки. Статичная выноска прячется, когда точка подъезжает к ней ближе 5% маршрута.
- **Янтарная изолиния только в радиусе вокруг точки.** На всю карту она выглядела как вторая дорога и путала.
- **Только тёмная тема — осознанно.** Это ночной навигационный инструмент, как в референсе. Цвета заданы токенами в `:root`, шейдер берёт их оттуда же через `getComputedStyle`.
- **Шрифты с кириллицей.** IBM Plex Sans Condensed (подписи), Golos Text (текст), IBM Plex Mono (цифры). Barlow, похожий на дорожные знаки, отклонён: в нём нет кириллицы.
- **Интерфейс блока на английском, пояснения на русском.** Интерфейс повторяет стиль референса (ABOVE SEA LEVEL, ft), пояснения — для русскоязычной команды. По умолчанию ft, как в референсе.
- **Масштабы:** 1 единица мира = 6 миль, высота в метрах = 180 + h × 1580, вертикальное преувеличение ≈1,8×.

## Где что настраивать в `index.html`

| Что | Где |
|---|---|
| Размер и разрешение сетки рельефа | `const X0 … NZ` |
| Форма рельефа | `function heightAt` |
| Вертикальный масштаб, перевод в метры и мили | `VS`, `E0/E1`, `MI_PER_UNIT` |
| Маршрут | `ROUTE_CTRL` (контрольные точки x, z) |
| Дороги в котловине | `ROADS` |
| Камера по умолчанию | `const BASE` и `resizeGL` (портретный режим) |
| Шаг горизонталей | `contourStep`, `uIdx` в `setUnit` |
| Скорость проигрывания | `PLAY_SECONDS` |
| Подписи и их приоритеты | `buildOverlay`, раскладка — `layout` |
| Цвета | CSS-переменные в `:root`, шейдер читает `--bg`, `--t-lo`, `--t-hi`, `--t-line`, `--alt`, `--route` |

После изменения рельефа или маршрута запустите `npm run profile` и проверьте, что перевал выше конечной точки и профиль выглядит правдоподобно.

## Отличие от опубликованного артефакта

В `index.html` добавлена обёртка (`<!doctype html>`, `<head>`, `<body>` и сброс стилей). Она помечена комментарием `standalone wrapper`. Публикатор артефактов claude.ai добавляет её сам. Чтобы опубликовать файл как артефакт снова, уберите строки от `<!doctype html>` до `<!-- /standalone wrapper -->`, строки `</head>` и `<body>` перед `<main>` и закрывающие `</body></html>`. Остальное содержимое совпадает с версией 1 артефакта.

## Как проверялось

- В облачном контейнере, где делался проект, cdnjs был закрыт. Поэтому страница проверялась локально с Three.js r128 из npm: Playwright + Chromium (SwiftShader), ширины 1280 и 400 px.
- Ошибок в консоли нет, горизонтального скролла нет.
- Проверены наведение на рельеф, переключение на метры и клик по профилю.
- Опубликованный артефакт (с загрузкой с cdnjs) в браузере отдельно не открывался.

## Что не доделано

- Не проверено на реальном телефоне: тап по рельефу (показ изолинии), свайп для поворота, производительность. Сетка 109 тыс. вершин и pixel ratio до 2 могут быть тяжёлыми для слабых устройств; если тормозит, уменьшите `NX/NZ` или ограничьте `setPixelRatio`.
- Карту нельзя вращать с клавиатуры. С клавиатуры доступны только профиль (`role="slider"`) и кнопки.
- Нет светлой темы.
- Нет автотестов, только скрипт скриншотов.
- Подсказка внизу карты выбирает текст по `@media (hover: none)`. На устройствах с мышью и тачем одновременно может показываться не тот вариант.
- Данные вымышленные. Возможные следующие шаги:
  - загрузка реального трека (GPX) и рельефа (DEM-тайлы);
  - расчёт расхода энергии для EV-сценария;
  - вынос блока в Web Component или React-компонент с API `progress` / `onProgressChange`.
